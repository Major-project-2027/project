# ONE requirements file for BOTH Render services (Flask app.py and
# FastAPI app/main.py) -- they share this same backend/ directory and
# the same Python environment, so there is no reason to split it in
# two. Versions are pinned to exactly what `pip freeze` showed in the
# working local dev environment (Python 3.13.7) after both services and
# the friend's integrated AI models (see services/friend_ai/) were
# verified running end-to-end. Deliberately excludes: Windows-only
# packages (pywin32, pypiwin32, win32_setctime, comtypes, pyttsx4,
# sounddevice -- none importable on Render's Linux containers, and
# nothing in the live code path imports them), and packages only used
# by the friend's UN-wired inference/voice + inference/face_authentication
# + inference/engagement modules (deepface, retina-face, librosa,
# soundfile, webrtcvad-wheels -- loader.py never calls into those).
# Everything else pip resolves transitively (e.g. the many small
# tensorflow sub-dependencies via tensorflow) rather than being pinned
# twice here.
#
# No torch/torchvision/ultralytics: object detection runs on ONNX
# Runtime against yolo11n.onnx/yolov8n.onnx (exported from the exact
# same weights, not retrained) instead of ultralytics.YOLO. Measured:
# torch/ultralytics cost ~267MB resident (import + model load + one
# real inference) vs onnxruntime's ~90MB for the identical detection
# job, verified to produce identical person/phone detections on real
# test images. This -- combined with removing a confirmed-dead Keras
# face-recognition load, lazy-loading the rarely-used "current" Keras
# emotion-model fallback, and converting the friend's (production
# default) emotion model to ONNX too -- was required to get the AI
# pipeline's real steady-state memory (~918MB measured with a real face
# in frame, not just import-time cost) down toward Render's 512MB
# free-tier runtime limit. See services/ai_service.py and
# services/friend_ai/loader.py for the per-component detail.
# =====================================================================

# dlib-bin, face-recognition, and face-recognition-models are
# deliberately NOT listed here. face-recognition declares a hard
# dependency on plain `dlib` (a different PyPI distribution from
# dlib-bin, which has no prebuilt wheel on most platforms -- pip falls
# back to a from-source cmake/C++ build, which is slow and was the
# other contributor to the Render build running out of memory). Both
# Render services' buildCommand in render.yaml installs dlib-bin first,
# then face-recognition/face-recognition-models with --no-deps, so pip
# never attempts to resolve plain `dlib` at all; only then does it run
# `pip install -r requirements.txt` for everything else in this file.
# Local dev: run that same two-step sequence once, in that order,
# before installing this file.
